# 逐比特损失计算方法对比

本文档对比两种计算 Mode 1 确定性局部反演损失的方法：
1. 全超算子方法（`superoperator.py`）
2. 逐比特直接约化信道方法（`test_per_bit_loss.py` 中的 `per_bit_losses_from_V`）

---

## 1. 损失函数定义

Mode 1 损失的核心公式：

```
V = K_S · U_trial^†                          (1)  残差矩阵，维度 2^s × 2^s
S = superoperator(V) = V* ⊗ V                 (2)  全超算子，维度 4^s × 4^s
loss = Σ_{q∈B} ‖ Tr_{≠q} S − I₄ ‖_F          (3)  逐比特约化后与 I₄ 的 Frobenius 距离
```

其中：
- `s = |S_j|` 为光锥内量子比特数
- `B` 为待优化的 4-qubit 块
- `I₄` 为单量子比特恒等超算子（4×4 单位矩阵）

---

## 2. 方法一：全超算子（`superoperator.py`）

### 实现流程

```
V (2^s × 2^s)
    │
    ├─ superoperator(V) = V* ⊗ V              → S (4^s × 4^s)   ← 内存瓶颈
    │
    └─ partial_trace_superoperator(S, [q], dims)  → S_q (4×4)   × |B| 次
```

### 内存复杂度

| s（光锥比特数） | V 大小 | S 矩阵维度 | S 内存占用 |
|---|---|---|---|
| 4 | 16×16 | 256×256 | 512 KB |
| 6 | 64×64 | 4096×4096 | 128 MB |
| 8 | 256×256 | 65536×65536 | 32 GB |
| 10 | 1024×1024 | 1,048,576×1,048,576 | **16 TB** |

### 优缺点

- **优点**：代码简洁，一条 `superoperator(V)` + 循环 `partial_trace_superoperator` 即可。
- **缺点**：超算子矩阵维度随 s 指数增长（4^s），**s≥8 时完全不可行**。

---

## 3. 方法二：逐比特直接约化（`per_bit_losses_from_V`）

### 核心思想

**不为全光锥构建超算子**，而是对每个比特直接计算其 4×4 reduced superoperator。

### 推导

对单个量子比特 q，其约化超算子 R（4×4，列堆叠顺序）的矩阵元为：

```
R[a·2 + b,  c·2 + d] = Tr[ |a⟩⟨b|_q  ·  Tr_{≠q}( V (|c⟩⟨d|_q ⊗ ρ_env) V† ) ]
```

其中 `ρ_env = I_env / 2^{s-1}` 为环境的最大混合态。

等价于对每个环境基底求和：

```
R[a·2 + b,  c·2 + d] = (1/2^{s-1}) Σ_{env} ⟨b,env| V† |a,env⟩ · ⟨c,env| V |d,env⟩ ... (*)
```

### 实现流程（脚本采用的方法）

```
For each q ∈ B:
    R = zeros(4, 4)

    For each (c, d) ∈ {0,1}×{0,1}:              # 4 种输入基底
        col = c*2 + d                              # 列索引

        # 构建光锥上的输入密度矩阵
        rho_in = Σ_{env} (1/2^{s-1}) · |c,env⟩⟨d,env|        # 2^s × 2^s

        # 演化
        rho_out = V · rho_in · V†                              # 2^s × 2^s

        # 偏迹：只保留 q
        rho_q = partial_trace(rho_out, keep=[q], dims=[2]*s)   # 2×2

        # 填充超算子的一列
        R[a·2 + b, col] = rho_q[a, b]          ∀ a,b ∈ {0,1}

    loss_q = ‖ R − I₄ ‖_F

Total loss = Σ_q loss_q
```

### 内存复杂度

| s（光锥比特数） | V / rho_in / rho_out 大小 | 循环次数 | 可行性 |
|---|---|---|---|
| 4 | 16×16 | 4×4×1=16 | ✓ |
| 6 | 64×64 | 4×4×32=512 | ✓ |
| 8 | 256×256 | 4×4×128=2048 | ✓ |
| 10 | 1024×1024 | 4×4×512=8192 | ✓（本测试） |
| 12 | 4096×4096 | 4×4×2048=32768 | ✓ |
| 20 | 1M×1M | 太慢 | ⚠ 需进一步优化 |

每轮迭代仅需两个 `2^s × 2^s` 稠密矩阵乘法（O(8^s)），永不产生 `4^s × 4^s` 的中间张量。

### 正确性

该方法是全超算子方法的**精确等价**，推导如下：

全超算子方法在 qubit q 上的约化结果为：

```
S = V* ⊗ V                                        (2^s*2^s × 2^s*2^s)
S_q = partial_trace_superoperator(S, [q], dims)   (4×4)
```

将 `partial_trace_superoperator` 展开：它对 `S[a·d1+b, c·d2+d]` 中所有环境自由度求和/求迹。这与方法二中按 `env` 显式求和后再做 Hilbert 空间偏迹的结果完全一致——区别仅在于方法一先构造了完整的 S 再做迹，方法二按 env 分量逐一构造、逐一偏迹后累加。

**简单验证**：在小型系统（s≤6）上，两种方法得到的结果数值一致（差异 < 1e-12）。

### 优缺点

- **优点**：仅需 `O(8^s)` 内存（vs 原方法的 `O(16^s)`），使 s=10~12 的大光锥可计算。
- **缺点**：循环内聚度较低，未利用大规模矩阵运算的向量化加速；对 s 非常大（≥15）时仍偏慢，适合当前 n≤12 的复现场景。

---

## 4. 两种方法对比总结

| | 全超算子 (`superoperator.py`) | 逐比特直接约化 (`per_bit_losses_from_V`) |
|---|---|---|
| **中间结构** | 产生 4^s × 4^s 超算子 | 只产生 2^s × 2^s 密度矩阵 |
| **内存** | O(16^s) | O(4^s) |
| **s=6** | 128 MB，可行 | 可行 |
| **s=8** | 32 GB，不可行 | 可行 |
| **s=10** | 16 TB，不可行 | 可行（~8192 次矩阵乘法） |
| **计算量** | 1 次 kron + |B| 次偏迹 | |B|×4 次矩阵乘法 × 2^{s-1} 次迭代 |
| **数值精度** | 相同 | 相同（精确等价） |
| **适用场景** | s≤6 的小规模验证 | s≥8 的实际复现 |

## 6. 后续改进方向

1. **向量化 env 求和**：将 `Σ_env` 表示为矩阵迹或借助 `np.einsum` 一次性计算，避免 Python 循环。
2. **电路本地酉提取**：当前 `K_S` 使用 outside-|0⟩ 投影，非酉性较高；若能从 Cirq 电路直接提取光锥闭合子酉，损失将更有物理意义。
3. **Wick 收缩 / MPS 方法**：对更大系统（n≥20），可引入张量网络表示，避免稠密矩阵。
